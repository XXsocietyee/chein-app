# US launch r1: same backend, Apple Pay + Stripe, +1 phone login (2026-11-27)

Owner 11-27: the player version launches in China and the US at the same time. US uses the **same backend** (`https://www.chengyinhub.com/prod-api/`), **Apple Pay + Stripe** for payments, and **SMS login with +1 numbers**. Merchant stays off. No secrets in git: keys come from server config / env and from xcconfig `Local.*` files that are gitignored.

Repos: app `https://github.com/XXsocietyee/chein-app` (base `origin/ui/combined-r7`); backend `https://github.com/XXsocietyee/hengyin` (base `origin/main` = production master snapshot 2026-11-24; Java/Spring "RuoYi" layout, SMS via `chengyinhub-common/.../sms/AliSmsUtil.java`).

## Lanes

| Lane | Repo / branch | Scope |
|---|---|---|
| be-us | hengyin `us/r1-backend` | (1) **SMS +1:** accept E.164 phone numbers (`+1XXXXXXXXXX`, `+86…`) on the SMS send/login/register/bind endpoints; route non-+86 numbers to Aliyun international SMS (number format `1XXXXXXXXXX`, separate `sms.intl.signName` / `sms.intl.templateCode` config, English template "Your Chengyin verification code is ${code}"); per-number + per-IP rate limits unchanged; keep +86 behaviour byte-identical. (2) **Stripe:** new payment channel `STRIPE` for orders whose currency is USD: `POST /api/pay/stripe/intent` (create PaymentIntent for an existing order; amount/currency from the order, never from the client; idempotency key = order no), `POST /api/pay/stripe/applepay` (confirm with an Apple Pay token → Stripe `payment_method_data[card][token]`), optional Stripe Checkout session URL for card fallback, `POST /api/pay/stripe/webhook` (verify `Stripe-Signature` with the webhook secret; on `payment_intent.succeeded` mark the order paid through the existing order-paid service, idempotent; on refunds use the existing refund flow → Stripe Refund API). Config keys `stripe.secretKey`, `stripe.webhookSecret`, `stripe.publishableKey` read from config; never logged. (3) Expose `paymentChannels` including `APP_STRIPE`/`APPLE_PAY` for USD quotes so the app's channel check passes. Unit tests with a stubbed Stripe client (no network). No production deploy. |
| app-pay | chein-app `us/r1-pay` | Apple Pay with `PKPaymentAuthorizationController` (merchant id `merchant.com.chengyinhub.chengyinApp`, `supportedNetworks` visa/masterCard/amex/discover, `merchantCapabilities .threeDSecure`, country US, currency USD) + `PKPaymentButton` (SwiftUI `PayWithApplePayButton` on iOS 16+) on the existing order/registration pay step when the order currency is USD and the channel list has Apple Pay; send the token to `/api/pay/stripe/applepay`; card fallback opens the Stripe Checkout URL in `SFSafariViewController` and returns via the existing order-status poll. China flow (WeChat/Alipay) untouched. Add `com.apple.developer.in-app-payments` entitlement with the merchant id. Money stays behind the existing Release money switch per market. |
| app-us | chein-app `us/r1-login-config` | (1) `Config/UnitedStates.Production.xcconfig`: same host `https://www.chengyinhub.com/prod-api/`; realm: reuse the China realm only if the backend has no market split — otherwise `us-prod`; write the reasoning in the receipt. (2) Phone login/bind/register: country picker (+1 United States, +86 中国大陆, default from `Locale.current.region`), E.164 send, US formatting `(555) 123-4567`, validation per country; Sign in with Apple stays. (3) US market composition: player features on, merchant off, currency/units from locale (coordinate with `i18n/r1-locale`). |
