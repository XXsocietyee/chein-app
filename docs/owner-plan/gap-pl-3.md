**Method and limits.** Evidence rows were gathered by four read-only passes over `App/`, `Core/`, `Tests/`. No Swift toolchain was available, so nothing was compiled or run; "test exists" means the test file was read or grepped. Several large Core files were read by header/key sections only, and a few rows cite file names without line numbers. Statuses are conservative: code that exists but is nil/off in the shipped composition is PARTIAL or GATED-BY-DESIGN, not IMPLEMENTED. Note the plan's own text says Swift/App/MySQL were never run for the "started" flows. Row counts come from my own splitting of plan sentences; the plan itself does not number them.

9. **Push/device & cache (CT12.d/f):** cache not keyed by account/object/privacy/version; push registration keyed by device id only, not wired to App (`Core/DevicePushRegistrationLifecycle.swift`).
10. **Governance/appeal & content publishing (CT13/CT14):** three separate appeal routes, no `audit_appeal` reuse proof; no publishable-type allowlist proof; N002 lacks reject-preference setting and blacklist uses unreviewed `api/native/blacklist/*` paths.
