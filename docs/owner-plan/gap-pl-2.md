## Loop verdicts

**EXEC-01 Loop verdict.** The mechanics exist and are well tested in Core/AppUnitTests: login restore (App/AppSession.swift:7423), 401 -> matching-session expiry with a non-secret notice (:7659, Core/SessionExpiryNotice.swift), logout that fences stale work and keeps the durable journal (:7598, SignOutConfirmationIdentityTests.swift:201). But the shipped artifact is `reviewed: nil` -> `.unconfigured` (App/RegionalLaunchConfiguration.swift:10), so no login or business request leaves the app in production. The loop is therefore GATED-BY-DESIGN and exercised only through fixtures/tests with a reviewed composition. Not found: a token renewal path, a 403 global policy, a capability-negotiation header, and an entry-by-entry state audit.

**EXEC-02 Loop verdict.** Only the "existing group" half exists: IM-group projection, rules-CAS admission, cancel/leave/pause/revoke-invite client with request ids, and Core-level revoke isolation. It is reachable in code from the chat-info page (App/IMExpandedViews.swift:283-310) but only behind the reviewed-production gates, and the management/onboarding/welcome approvals are never issued (App/AppCompositionRoot.swift:336,353,354). There is no invite landing/deep-link intent, no channel-create path, no server `joinState`/effective-permission DTO, and no per-item rules agreement. The create -> join -> use -> exit loop does not exist end to end; the card itself calls the new channel LATER, so this is expected, but nothing here is a production entry yet.

**EXEC-03 Loop verdict.** List -> chat -> history -> unread badge are real views (App/MessagingHomeView.swift, App/MessagingHistoryView.swift, App/IMInboxViews.swift:135) reachable from the Club tab toolbar and Me row once a session has the messaging-history lease. Send/read-ack/mute writes are built (Core/IMExpandedCoordinator.swift, Tests/CoreTests/IMExpandedTests.swift:96,177) but docs/parity/page-map.csv:37 and hook-wiring.md:49 mark them dormant/unwired, and the production `sessionDependencies` that admits them is only active under a reviewed deployment. The recovery half (same request id, unknown outcome retained, late-response fencing) exists in Core. Missing: CT03 mention-from-reply, sender-visible "in review" state, monotonic unread-total guard, unread-summary lease, push de-dup, and two triaged failing proof tests (NativeChannelMessageHostBindingTests, NativeChannelMessageOriginalWriterJournalTests). End-to-end is not demonstrable from a production entry today.
