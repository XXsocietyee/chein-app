## How to read this

- **Owner**, exactly one of:
  - `CLAUDE-FIX`: Claude can fix it in this repo with no external input.
  - `OWNER-ONLY`: needs an owner decision or credentials/accounts/legal input. **Marked in bold with a stop sign: 🛑 OWNER-ONLY.** Claude must not guess these.
  - `BACKEND-GAP`: the backend (`chengyin`, `integration/20261106/backend-latest`) lacks the route or behaviour. The iOS side can only gate, rename or work around.
- **Test** names: an existing file is shown plainly. A test that does not exist yet is marked `(new)`. These are proposals; none were run.
- **Confidence**: the reports are static analysis (nothing compiled or run). I re-checked these claims against the repo myself: no `.entitlements` file and no `CODE_SIGN_ENTITLEMENTS`/`CFBundleURLTypes`/`associated-domains` anywhere in `Config/` or the pbxproj (B1, B3); `PRODUCT_BUNDLE_IDENTIFIER = invalid.example.questify.ios` (B2); `AuthService.login(username:password:)` posts only `username`+`password` to `.password` (E1); `deregister/result` is read in `Core/AccountDeregistrationOriginal.swift` (E2). Everything else is carried over from the reports as stated and is tagged **(unverified by me)** where it depends on a backend, a runtime flag or a device.
