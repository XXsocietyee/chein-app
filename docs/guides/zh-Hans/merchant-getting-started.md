# 商家入门

商家账号是一家店：可以承接一站、处理服务器分给这家店的订单，并维护店铺资料。点「成为商家」不会授予这个账号。服务器在申请通过、并且访问检查显示账号已生效之后，才会授予。

本页按仓库里已经写明的小程序商家路径说明：申请、回读状态，以及只有在授予之后才能看到的工作台。

> 审定文本尚未提供。阅读本页不算同意。

## 从哪里开始

两个入口打开同一份申请：

- 首页主视觉：「成为商家」。
- 设置：「成为商家」，和「俱乐部主理人」在同一组。当前账号还不是商家时才显示。

两者都是申请。都不会在设备上切换底部标签，也不会编造一个商家角色。

小程序里，已生效的商家账号使用五个标签：工作台、营销、模板、合作、我的。在 iOS 上，这些入口只在服务器标明商家账号已生效、并且该页权限存在时出现。看不到某个标签，就是还没有这项授予。

## 提交之前

源流程把这一步叫作登记，不叫作已核验身份。表单会先问发布者身份是否已经登记。没有登记时，不能上传，也不能提交。

现有登记使用中国大陆身份校验。本指南不印出那张表、证件号码，或其他国家的替代字段。这里不收集美国入驻字段，因为那份契约没有提供。如果 App 写明需要身份，或查询失败，就停在那个页面。查询失败和「未登记」不是一回事。

必须已登录。身份未登记或未确认时，不能上传执照，也不能发送申请。

## 申请表

表单分四步。必填是店铺名称、电话、地址、营业时间和执照照片。简介、偏好和微信是可选项。电话栏不另造国家区号规则。

1. 店铺名称和电话。
2. 地址和营业时间。时间沿用源流程的星期和时间写法。时间选择器可以取消，草稿保持不变。
3. 执照照片。先选一张图，看预览，再单独确认上传。选中照片不等于已经上传。草稿只在上传成功之后，或在服务器退回的被拒申请里，才保留执照引用。没有手填网址的输入框。
4. 核对。确认后这份草稿被冻结。取消或再次点击不会再发一份。发送前，App 会再读一次申请状态和身份登记。任一变化都会停下。

定位只在你选择地点时请求，用来匹配承接范围。说明文字写明：拒绝定位后仍可以继续填写其他资料。

服务器确认收到提交后，App 只回读一次状态。这份回执不是通过，不是开通，也不是商家角色。结果未知时不要再提交。去读状态。稍后的读取如果看起来没变，也不能证明第一次发送失败了。

## 每种状态是什么意思

这些状态彼此分开。停用优先于其他状态，并且不会借用旧的拒绝理由。

| 状态 | 含义 |
| --- | --- |
| 没有申请 | 服务器明确说没有申请。请求失败不是这个状态。 |
| 审核中 | 已提交。等待。不能在本地把它改成通过。 |
| 已拒绝 | 服务器给了理由。只有这个状态可以把服务器确认过的字段填回新申请。坐标和微信不会被抄回来。 |
| 待开通 | 已接受，还不能经营。 |
| 已生效 | 可以打开工作台。工作台每次进入仍会检查访问权限。 |
| 已停用 | 账号被停用。停用理由是单独的文字。 |

经营上的拒绝保留服务器原文。App 不会编造一条和俱乐部主理人永久冲突的规则。

## 账号生效之后

工作台显示服务器返回的店铺和角色。账号未生效时，不显示经营入口。

能看到什么取决于权限：

- 店主可以看待办和最近动态。
- 营收和近七日金额还需要财务读取权限。其他角色看不到这些数字，App 也不会去请求。
- 没有金额时是破折号，不是零。这一页的金额是商家源数据里的人民币记录，按服务器返回的样子显示。

订单使用服务器认识的状态筛选和售后筛选。可以下拉刷新。一行打开的是这份列表里已有字段的只读摘要，后面没有另一次详情请求。

商家承办的项目和个人项目是两份列表。第一页就是服务器返回的那一页。如果服务器说还有更多行，页面会说明列表不完整，不会编造下一页。

工作台在权限允许时可以打开的店铺工具包括：店铺资料、店铺装修、图集、品牌故事、承接设置、店铺角色、声音和形象资源、城市点位目录，以及店铺自己的互动模板。这些页面的保存保持关闭，直到对应的写入被打开。预览不是已发布的店铺。图集最多九张。新建互动模板时不预选完成方式，由你来选。私有模板不是公开模板页。

承接设置可以记录容量，以及收费是免费还是付费，取值是 0 和 1。无法识别的收费保持未知。缺省不等于免费。

## 承接一站，或主办一场活动

报名承接一站，不等于接上了这一站。表单上的话是：报名成功不等于中标，主理人确认后才算接上这一站。你要选地点、日期区间、可用空间和现场条件，以及至少一张场地照片，最多九张。能拍成 5:3 横图时按这个比例。

主题已经开始、报名已经通过，或状态在你填写时变了，就不能再改这份承接。回到详情看最新结果。

商家主办的活动目前不能填票价。校验写明还没开通收款，票价只能是 0。不要在那张表上填付费票价。

不是商家、却要卖付费票的发布者，必须已经完成发布者身份登记。活动向导会在核对前要求这一点。

## 订单、退款，以及本页不写的内容

订单状态和售后状态是服务器给出的代码。无法识别的代码保持数字，本页不另起名字。

售后详情可以显示退款单号、活动、已知的金额，以及订单上的政策快照。商家意见本身不是退款。平台步骤只在服务器已经记录之后才出现。App 不编造到账时间。

退款的客服交接使用上面的联系方式占位。本页不写具体的人或聊天号。

本指南不说明银行卡提现，也不说明虚拟商品。App 能读到的打款记录是历史，不是一张新的转账表。

## 页面不动的时候

- 点商家入口永远不会授予访问权限。状态回读写明已生效之后再打开工作台，并且预期那个页面会再查一次权限。
- 审核中、已拒绝、待开通、已生效、已停用不能互换。不要保留已停用账号上的旧拒绝理由。
- 提交一直忙碌或写明结果未知时，不要再次确认。去读状态。
- 有财务权限的店员看不到店主的待办。没有财务读取权限的店主看不到营收。
- 上传、核销和店铺发布以实际打开的页面为准。灰色的控件表示这项写入是关的。
