## The `{}` rows

`/api/{}/cancel` and `/api/{}/cancel_preview` come from Swift string interpolation, not from a literal: `PublisherLifecycleCoordinator.swift:87` is `"api/\(resource.kind.rawValue)/cancel"` and `PublisherLifecycleHTTP.swift:80` is `"api/\(resource.kind.rawValue)/cancel_preview"`. The Appendix A generator normalises `\(...)` to `{}`, so the row looks malformed. `PublishedResource.Kind` is `topic|activity|template` (`PublishModesDomain.swift:22`), but `paidPlayers` throws for template (`PublisherLifecycleHTTP.swift:77`) and the read allow-list (`:69`) names only `api/topic/cancel_preview` and `api/activity/cancel_preview`, so only topic and activity are reachable. The backend serves both. Note: the main table already lists `/api/topic/cancel` (fixture row, line 1028) and `/api/activity/cancel`; the `{}` rows are duplicates, not extra work. The other trailing-slash rows (`.../owned/`, `.../reward-pledge/`, ...) are the same kind of artefact from `"prefix/" + variable` concatenation.
