## What was wrong before this branch

The P7/P8/P9 screens (`JourneyReportView`, `JourneySettleView`, `JourneyRankBoardView`) were already built. The App binding behind them (`PlayerJourneyProjection` in `App/PlayerJourneyReadBindings.swift`) read keys the server does not send:
- Report: `nodesText`, `elapsedText`, `dateLabel`, `rewardItems`, `penaltyText`, flat `score` and `rank` numbers, `nodes[].id` / `mode`, and the result from `runState` (`COMPLETED` never matched). With real data every screen showed em dashes, "not scored" and no result word.
- Memory: `moments` were never read (always `[]`); `photoShareCapability` was ignored.
- Rank: read `rows` / `list` instead of `entries` / `me` / `coverage`, never checked that the answer was the board asked for, sent the activity id as the quest `scopeId`, and called the team-to-team ranking with owner type 2 + a run id (2 is an activity) under the "My team" (队内) label.
- Finish medal screen: always said 主题通关 from local completion and "获得 max(N,1) 枚勋章", i.e. at least one medal even when none came back.

## Decisions where the docs were silent or off

- The P7 report fields come from `PlayerRunReportVO` and `journey-view.js reportView`, not from the §24.3 table's short list. The table names `score`/`rank` as numbers; the real VO nests them as objects.
- Feedback lives in the battle report, not the finish sheet: the mini-program has no caller yet, and §25.2 puts 报告问题 on the existing support entry tied to the run/stop without answers, tracks or photos.
- Feedback is not added to the production owner grant. That needs the owner's approval; until then `sendsRunFeedback` is false on the reviewed host and the row is hidden instead of failing as "unknown".
- A 2xx feedback answer without a receipt is treated as unknown, not success. Because the source clears the saved id on any non-5xx answer, the re-check then reports "not sent" instead of replaying; this is the conservative side (no fake success).
- `JourneyLoopSource.Journey.runFeedback` is not a `journey-api.js` export; the case comment says so.
