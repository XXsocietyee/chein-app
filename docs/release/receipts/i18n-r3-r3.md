**Checker (`tools/check_l10n.py`).** A bilingual pair split over two lines now counts as localized, the same rule as the existing same-line pair. Both orders count: `text(\n "中文",\n "English")` and `c("English",\n "中文")`. So does `? "中文"\n : "English"`. Two guards:
- The English half must not be a dotted catalog key (`zeroHP.copy.017`).
- The English half must not open a dictionary entry (`"RESET": …`).

I sampled 45 of the newly accepted lines; all were real zh/en pairs after the two guards. This alone accounts for about 118 of the 426-literal drop. The other ~310 are real conversions.

## Risks for first compile

- `CYBusinessCopy` is `public enum` with `public static var`s; it's used as default argument values of `public init`s, so defaults reference only public symbols. `text(_:)` is internal (not used in defaults).
- `appLocalized(cond ? "a" : "b", locale:)` and `CYBusinessCopy.text(isBuyer ? "a" : "b")`: ternaries of string literals typed as `String.LocalizationValue`. `DisclosureGroup`/`Button` titles with a ternary are wrapped in `LocalizedStringKey(...)` so the String overload can't win.
- `CYStatusChip(cond ? "a" : "b", tone:)` uses the unlabeled `LocalizedStringKey` init.
- `Text(LocalizedStringKey(item.name))` for catalog data: a name with `%` would be treated as a format. None of the 33 places has one.
- `appLocalized(String.LocalizationValue(strip.city.name), locale:)` follows the `AccountComplianceViews.swift:309` precedent.
- `ModUpgradeFrozenComparisonView.changeLabel(_:)` now returns `Text` (it was `String`), and its only call site was updated. `fact(_:_:)` takes `LocalizedStringKey`.
- `TopicPurchaseRevealBuilder.model` gained `locale: Locale = .current`; the single caller is unchanged.
- Added `@Environment(\.locale)` to `RoamEntryPeekView`, `GeocodedAddressButton` and `ModUpgradeFrozenComparisonView`.
