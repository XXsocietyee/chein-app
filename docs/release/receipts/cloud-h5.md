## Other decisions recorded
- **Invitation preview bug (fixed):** since j4 F10, `/api/team/info` with an invite code strips `memberId` from member rows for non-members. The old `TeamMember` decoder required `memberId > 0`, so every invitation page that had a member (always at least the captain) failed with `invalidContract`. Preview rows now decode with negative local ids and `identified=false`, and can never be a remove target. A joined viewer must still receive ids for every row; partial ids are rejected.
- **Co-device vs independent accounts** (§七 U06-01 补齐): B6 has no co-device count, so nothing is drawn. Joined count (`joined_count`) and paid-valid count stay separate rows.
- The write path stays on the existing `/api/team/{join,quit,kick,disband}` adapter with its persisted operation journal and the unknown → receipt-check rule. The mini-program uses `/api/team/command` with a `requestId` receipt. The app's `TeamCommandWriter` is still unused: it reads only the HTTP status, not `data.state` (APPLIED/REJECTED/UNKNOWN), and sends no Authorization header. Adopting it is a follow-up and was not needed for these cards.
- Money, merchant and password controls were not touched. TICKET_REQUIRED shows copy only and offers no purchase entry.
