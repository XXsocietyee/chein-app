## Behaviour changes

- `unlock-chapter` used to send only `activityId`, which the backend refuses ("必须提供命令标识、期望章节和目标章节"). It now sends the
  frozen `{commandId, expectedChapterId, targetChapterId}` taken from team-progress (`currentChapterId`, `nextChapterId`).
  - An unknown outcome (520, transport, or a receipt that does not match) only re-reads `unlock-chapter-receipt` with the same id.
  - A 409 with `intentNotExecuted` offers "End the original request".
- Leader station release: team-progress `skipRequests` (up to 8) show as rows. Each row asks for confirmation, then sends one POST and
  reloads team progress.
- Guard appeal: the entry is persisted per owner and play session (`play-guard-appeal:<owner>:<session>`, read back after each write).
  - An unresolved submitted command is never replaced.
  - After a submit, only the receipt is read with the frozen request id.
- Myproject: rejected or offline topic and activity cards get a "Review record" row. The row opens the timeline, the appeal (only when
  `canAppeal`), and the original-receipt recovery. The draft key is `audit-appeal:<owner>:<bizType>:<bizId>`.
