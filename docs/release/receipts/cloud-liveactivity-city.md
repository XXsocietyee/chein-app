## What was done

An ActivityKit Live Activity for two flows, with Lock Screen and Dynamic Island compact, expanded and minimal
presentations. It uses system fonts, system colors and SF Symbols only; no restyle of existing screens.

| Flow | Shows | Starts | Updates | Ends |
|---|---|---|---|---|
| Live roam walk (`RoamLiveSessionController`) | distance, elapsed time (system timer), places revealed (unique confirmed POIs + shops) | first change with a local record in `.active` | every controller change (pulse, pause, resume, visits) | `.finished` (stays briefly with its final values), or no record / `.ready` / `.unavailable` / `.locationDenied` / `invalidate()` (immediate) |
| Active play session (`PlayExperienceCoordinator`) | topic title, current stop (name and n/N), clue progress (done/total), run timer (city-orientation runs only) | snapshot loads with availability `.active` | snapshot changes, `startRun`, `pauseRun`, `endRun`, run restore | route `.completed` or run ended (final values), snapshot cleared / `invalidate()` / unavailable (immediate) |

- Paused walks or runs show a frozen time and a "Paused" line. `recoveryRequired`, `recovering` and `finishing` show as paused.
- The roam controller's display clock is foreground-only. While the screen is locked, the mapping keeps the
  previous timer anchor, so the Lock Screen timer keeps counting from where the app left it.
- At most one activity per kind. A play update for a different session key ends the old play activity first;
  an `end` from one play coordinator never ends another session's activity.
- Activities left by a killed process are ended at launch (`QuestifyApp.init`).
- Local updates only: no push token, no new server endpoint, no new permission prompt. When Live Activities are
  off in Settings, `Activity.request` is skipped and the in-app flow is unchanged.
- **No App Group needed.** ActivityKit carries all content state; the extension reads no shared storage.
