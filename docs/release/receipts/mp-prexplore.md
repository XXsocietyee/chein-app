## Left for Cursor (logic)

- **infomation list count**: `PlayGuideInformationListPage.project` needs the raw body and status (for `total`). `SocialAccountReading.informationList()` returns only decoded rows, so the view cannot show `documentCountText`. It needs a reader that exposes the list receipt, or a `PlayGuideInformationListCoordinator` on the reader.
- **official list**: the phase is projected from the success payload only. `OfficialReadScreen` still owns loading and error, so the model's `.unknown` (malformed payload) currently surfaces as the generic issue view.
- **organizer**: `OfficialOrganizerConsoleModel.load` still substitutes `OfficialOrganizerEventState(status: nil, control: nil)` for a nil read. The view now records `eventMissing` alongside it. Cursor may want this in Core.
- **search2**: `GlobalSearchParityPresentation.resultTabs` still takes `Int` counts (the view bypasses it for badge text). `placeholderCopy` / `emptyQueryHint` still mention merchants.
- **square detail**: `SquarePost` / `SquareComment` still decode missing counts as 0. The view does not have the raw payload that `resolvePost` / `resolveComments` need. Kept minimal because of ui/mpsocial2.
- **topic**: `TopicXcxFacts.duration(nil)` still returns `.zero` in Core (the view now guards nil). `TopicThemeCardView` nil quantity and the unknown `productType` are unchanged.
- **pricing**: `grants.pricing` stays nil, so confirm is hidden in shipping builds. That is intentional; it is not enabled here.
- Not run: Swift compile, unit tests, simulator. No screenshots were taken or shared.
