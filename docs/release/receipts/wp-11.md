## Decisions taken

- **When-In-Use only, no Always key.** The brief said "'always' only when the session needs it". PROPOSED D-07 says "When-In-Use permission with the system background indicator, not Always", and the package row says "no Always key". I followed D-07. With `UIBackgroundModes: location`, `allowsBackgroundLocationUpdates` and `showsBackgroundLocationIndicator`, a When-In-Use roam that starts in the foreground keeps receiving fixes after Home. If the owner wants Always, it is one `requestAlwaysAuthorization()` call in `SessionBackgroundLocationTracker.startUpdates` plus the Info.plist key.
- **Play is foreground-only, roam is background.** This ports `mp:pages/play/index.js:5317` (`foregroundOnly: true`, stops on `_themeHidden`) and `mp:pages/roam/index.js:4118` (background hold, stopped only by `_stopReal`).
- **Privacy manifest:** no change needed. `NSPrivacyCollectedDataTypePreciseLocation` is already declared (`Resources/PrivacyInfo.xcprivacy:37`).
- **Older guards updated:** these contract checks encoded the old "no background location" rule: `test_app_store_privacy_launch_contracts.py`, `test_cb51_diagnostics.py`, `tools/archive_unsigned.py` and `tools/check_platform_consumers.py`. They now allow exactly `UIBackgroundModes = [location]` and still forbid the Always keys, `INFOPLIST_KEY_UIBackgroundModes` and the `audio` background mode.
