## Decisions where the docs were silent or differ

1. **Action-context binding is a reviewed capability.** `PlayExperienceCapability.actionContextBinding` is added to the production player set (`ReviewedPlayerWriteLeases.playCapabilities`) and absent from fixtures, so existing tests that script exact request order are unchanged. Without it the old request shape is sent (legacy behaviour).
2. **`locationTimestamp`** (epoch ms from the measurement) is sent only on context-bound intents, so a journal written by an older build replays its original fingerprint (backend hashes the field when present).
3. **Settled vs unknown.** A refusal settles the intent only with `intentTerminal`, `newActionIdRequired` or `intentNotExecuted`, and never with `receiptState` / 520. `INTENT_ACTION_REUSED` is a conflict, not a failure: the backend states the original's outcome is unknowable. Replies without contract fields (older server) keep the existing unknown handling.
4. **Replacement stops** follow the mini-program: server ids filtered to known, open, not-done stops, names ≤ 24 chars; `fallbackMode` set by the author is not an authorisation.
5. **Scan instead** is a hint, not a button: the native review path does not accept scan evidence on an arrive-only stop, so no button pretends it does.
6. **Download hosts** are limited to the accepted artwork hosts (`session.playKitArtworkHosts`), over an ephemeral HTTPS session with no cookies or account token.
7. **Shared-runtime submits** (`api/game/session/*`, `PlayPlayerRuntime`) already had their own requestId + receipt recovery; unchanged.
