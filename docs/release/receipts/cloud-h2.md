## Decisions where the docs were silent or differ

1. **Separate grant.** The two reads get their own runtime feature `projectPublicationRead` (exact GET only) and their own composition-root branch; they never ride on the editor's POST read/write grants. If the deployment does not grant them, the editor shows "isn't available in this build" and nothing is guessed.
2. **Route mark.** `/api/topic/publish-status` is marked `missing` in `ChinaReviewedRouteCapability` (not on production `014fc0d8`); counts in its test bumped 996 → 997 and 374 → 375. `publish-check` was already live.
3. **List `state` is not approval.** Mini comment BL-120 calls every time-bucket state "post-approval", but the backend VO states `status=1, checkStatus=0` is public-before-review. The app follows the backend: list shows visibility only.
4. **Server location first.** `chapterTitle` / `nodeName` from the backend win over the mini field mapping; the field mapping is kept as the fallback for old servers.
5. **Merchant / money off.** The mini "去招商家承接节点、找俱乐部带团" success line is not copied; the fallback next step only points to the status facts. Sale facts are shown as on sale yes / no + server reason, no amounts.
