# ui-pass-card receipt (DES-e4, W1-5)

Source: `/Users/fanning/chengyin-refs/specs/ux-strategy.md` W1-5. The four-tab IA (W1-1) is unchanged: no tab removed or renamed.

## What changed
- New `App/TicketPassSheet.swift`: `TicketPassSheet` (sheet on a `NavigationStack`) and `TicketPassCard` (notched `CYTicketPassShape`, `CYStatusRibbon`, 240 pt code tile on white, `cyBrightnessBoost` while the ticket is `.ready`). Loading, empty, failed and signed-out states use `CYPhase` + `CYStateView`; unknown date or place is an em dash.
- `AccountView`: the existing "tickets" tile on the member identity card now opens the pass sheet instead of the wallet list. Same entry point, same `session.ticketWalletReader`.
- Ticket lifecycle moved into the overflow (ellipsis) menu: ticket details and changes (the existing `TicketWalletDetailView`, so cancel/refund/team paths are unchanged), all tickets (hands off to the existing `TicketWalletView` sheet after this one dismisses), refresh, and a ticket picker when more than one ticket opens a detail.
- `VerificationCodeView`: new optional `embeddedQRSide` (nil = old layout, byte-for-byte same behaviour). Embedded mode drops the hero header and own scroll and draws the QR at the given side on white.
- Lead ticket rule `CYPassCardPick`: first `.ready` detail ticket, else first non-retired detail ticket, else first row.

## Taps to the QR
Before: Account tab, tickets tile, wallet row, "Present pass", then the code = 5.
After: Account tab, tickets tile = 2. Not changed: the code stays approval-gated (`VerificationCodeCoordinator.phase == .review` still shows its existing "show" button); that gate is behaviour and was not touched, so a ticket that is still in review needs that one extra tap.
