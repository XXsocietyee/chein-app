# ui-pass-card receipt (DES-e4, W1-5)

Source: `/Users/fanning/chengyin-refs/specs/ux-strategy.md` W1-5. The four-tab IA (W1-1) is unchanged: no tab removed or renamed.

## What changed
- New `App/TicketPassSheet.swift`: `TicketPassSheet` (sheet on a `NavigationStack`) and `TicketPassCard` (notched `CYTicketPassShape`, `CYStatusRibbon`, 240 pt code tile on white, `cyBrightnessBoost` while the ticket is `.ready`). Loading, empty, failed and signed-out states use `CYPhase` + `CYStateView`; unknown date or place is an em dash.
- `AccountView`: the existing "tickets" tile on the member identity card now opens the pass sheet instead of the wallet list. Same entry point, same `session.ticketWalletReader`.
- Ticket lifecycle moved into the overflow (ellipsis) menu: ticket details and changes (the existing `TicketWalletDetailView`, so cancel/refund/team paths are unchanged), all tickets (hands off to the existing `TicketWalletView` sheet after this one dismisses), refresh, and a ticket picker when more than one ticket opens a detail.
- `VerificationCodeView`: new optional `embeddedQRSide` (nil = old layout, byte-for-byte same behaviour). Embedded mode drops the hero header and own scroll and draws the QR at the given side on white.
- Lead ticket rule `CYPassCardPick`: first `.ready` detail ticket, else first non-retired detail ticket, else first row.

## Follow-up: status chip replaces the diagonal ribbon (TicketPassCard)
The corner ribbon clipped its text on the pass shape. `TicketPassCard` now shows `CYStatusChip` (existing tones and symbols from `CYPassState`) at the top-right of the cover band, on a solid `bgElevated` capsule so it reads over the art, single line with shrink; at accessibility sizes it moves below the band above the title and may wrap. VoiceOver: one element labelled with the status text (`ticketPass.status`). The ribbon id `ticketPass.ribbon` is gone (no references in App or Tests). `CYStatusRibbon` itself is unchanged and still used by the wallet card.
QR check: with the app's `verificationCodeFactory` (injected in `QuestifyApp`) and a `.ready` ticket the tile is `VerificationCodeView`, which draws a real CoreImage QR from the validated server payload. The example text/number fallback shows only when there is no factory (offline-example fixtures) or the ticket is not ready. Parse, scaffold and lint pass; not built or run.

## Follow-up 2: chip size, watermark, ticket details and wallet card
- Chip text: the pass-card chip no longer uses `singleLine()` (its 0.7 shrink made ~10 pt); it is `.caption` (12 pt) scaling with Dynamic Type, wrapping at accessibility sizes. Shared as `CYPassStatusChip` in `CYTicketPass.swift` (solid backing, one VoiceOver element labelled with the status).
- Watermark: `E1CoverArt` gets `symbolPoint`; both pass cards move the generated-art ticket glyph from top-right (0.8, 0.24) to lower right, clear of the chip and the title.
- `E1TicketCard` (ticket details / wallet detail, `e1-ticket-holder-expired`, `ticket-detail`) drops the diagonal corner ribbon for the same chip at the top-right of the band (below the band at accessibility sizes). Identifier `ticketWallet.detail.ribbon` became `ticketWallet.detail.status` (no references in App or Tests). No `CYStatusRibbon` call sites remain; the type is left in the kit.
