# Receipt: design/p1-shell-signin (backlog P1, lane L1 Shell & sign-in)

Base: `origin/ui/combined-r7`. Checked first: `fix/backlog-p0`, `native-r2/island-r1`, `native-r2/motion-r1`, `native-r2/sheets-r1` had no unmerged edits to the L1 files (island/motion are merged into combined-r7; p0 and sheets touch other files), so this builds on the combined-r7 tip.

- P-001 done: the five `.cyFloatingTabBarClearance()` calls are gone from `App/QuestifyApp.swift` and the modifier is removed from `App/DesignSystem/CYNightTabBar.swift`. The system `TabView` insets tab content itself. `cyTabBarClearance` (default 0) stays for the map scaffold.
- P-002 done: `.id(session.account?.id ?? 0)` is gone from `playerTabs`, so signing in keeps every tab's navigation and scroll state. The per-tab `.id(session.sessionRevision)` stays.
- P-004 done: every sign-in callback in the shell (`requestSignIn()`) opens one `LoginView` sheet (`cySheet`) over the current tab instead of switching to 我的. The new `RootSignIn` environment (`App/RootSignInEnvironment.swift`, `rootSignIn(then:)`) runs a resume action once the sheet closes with an account. The account entries (`openAccountOrSignIn()`) go to 我的 when signed in. Sign-in success: island `.status(.success)` (or a VoiceOver announcement when the island is off) plus `.sensoryFeedback(.success)`. Note: existing `onSignIn: () -> Void` callers pass no action, so for them "resume" means the screen stays mounted where they were; adopting `rootSignIn(then:)` per call site belongs to the owning lanes.
- P-005 done: `LoginView` is one sheet with a `NavigationStack(path:)`. The phone page (`AuthChannelView(embeddedModel:…)`) and both legal documents push inside it. The 2nd sheet (channels) and the 3rd/4th (legal) are gone. The one remaining extra sheet is `UsageConsentSignInRequirement`'s agreement review, and it only appears when the launch agreement was declined.
- P-006 done: Sign in with Apple (system `ASAuthorizationAppleIDButton`) sits on the first sign-in screen when Apple is configured and the agreement is on record. The phone page shares the same `AuthChannelModel` (`LoginAuthChannelHost`), so a push doesn't restart a running authorization. The embedded phone page has no duplicate Apple button.
- P-007 done: the welcome screen opens on a live MapKit `Map` showing a bundled sample walking route (People's Square → the Bund) that draws on through `NativeR2DrawOn`, with start/finish `Marker`s and `UserAnnotation` (only shown if location is already allowed; no prompt). It makes no network request of its own. Respects Reduce Motion and the motion flag, scales with Dynamic Type, and VoiceOver reads it as one labelled image (`welcome.sampleRoute`). The decorative app icon was removed.
- P-008 done: the agreement is asked once. The welcome checkbox shows only when no agreement is on record, and it stays visible after it is checked so VoiceOver focus doesn't jump. The sign-in sheet shows the review section only when no agreement is on record, and shows the "by signing in you agree" sentence only then. The pushed phone page no longer repeats the legal note (`PhoneSignInForm.showsLegalFootnote`).
- P-009 done: at accessibility text sizes the welcome buttons scroll with the content instead of being pinned (`dynamicTypeSize.isAccessibilitySize`). The consent row moved out of the pinned footer into the scrolling content, so 先逛一逛 no longer covers the consent footnote. The sign-in sheet's pinned bottom bar became form sections (the phone button row and the legal footer), so it scrolls at AX5 too.

Strings: `docs/port/strings/native-r2-l1-shell.json` was merged into `Resources/Localizable.xcstrings` (zh-Hans + en, 5 keys). Identifiers kept: `welcome.*`, `auth.close`, `auth.otherChannels`, `auth.signIn`, `auth.error`, `auth.channels.*`, `rootTabBar.tab.player.N`. New: `welcome.sampleRoute`, `auth.legal.agreement`, `auth.legal.privacy`.

Gates: `python3 tools/check_scaffold.py` gives PASS structural checks. `python3 -B tools/check_a11y_lint.py` gives PASS. Contract tests that grep the changed files were updated to the new intended behaviour: `test_auth_entry_parity`, `test_global_chrome_domain_contract` (tab clearance assertion), `test_pkg19_login_deletion_chain` (phone visibility argument), `test_remaining_native_clients`, `test_roam_account_entry`, `test_wechat_app_auth`. These failures were already on the base and are in files outside this lane: `test_global_chrome_domain_contract.test_pinned_footer_bars_use_cy_footer_bar` and `test_pkg19_login_deletion_chain.test_sign_out_entry_requires_confirmation`, plus 8 other modules that also fail on the base.
