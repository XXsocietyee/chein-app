## Open app findings (for Cursor)

- **N1: IM recipient preview never issues.**
  - Set `.environment(\.imRecipientPreview, …)` on the conversation views (`MessagingHistoryView` and
    `NativeChannelMessageBubbleView` parents).
  - Use `.ready` with one lease per template from `ReviewedProductionGateLeases.imPreviewLease(context, conversationID:
    <server conversation id>, template:)` (`App/ReviewedPlayerWriteLeases.swift:836`).
  - The conversation ID must be the decoded server conversation, and the message passed to `issue` must stay the decoded
    record (security condition; `Tests/ContractChecks/test_im_preview_lease_conversation_source.py`).
  - Add a hosted test showing that a message from another conversation shows "Refused".
- **N2: the entry-code clock tolerance is 5 s** (`Core/VerificationCodePresentation.swift:49`).
  - Real phones can be skewed by more than that.
  - Consider measuring the skew from the response `Date` header, or allowing a larger bound. Either way the code must still
    never outlive the server's absolute `expiresAt`.
  - This is a product and security decision, so I did not change it.
- **N3: bottom content is unreachable behind the floating tab bar (escalated from the 20261113 minor list).**
  - On the activity page the final "More info" card, which holds the only play entry (`activity.openPlay`), stays under
    the pinned action bar and the tab bar at the end of the scroll.
  - On club detail, "Club group chat" and the post like buttons sit under the tab bar until the page is scrolled.
  - Fix it at the tab root, not per screen: give tab content a bottom content margin equal to the floating bar's height.
  - Separately, a registered player's primary action should open play when `playReaderForActivity` exists, instead of
    opening the wallet.
- **N4: workshop purchased library.** `workshopPurchasedReadApproval` keeps its default `nil` in the shipped composition, so
  "Purchased packages" says "not configured" even with the TEST switch on. Grant it for China signed-in accounts when
  `ReviewedAreaSwitch.paymentsOpen` holds.
- **Minor:**
  - The Passport counters show "—" (R10 remainder: read `api/user/info` counters).
  - The team review sheet shows "not available" before a create that succeeds.
  - The ticket detail says "Redemption codes are not available in this native version yet", next to a working Present
    pass code.
  - Settings search finds no sign-out.
  - The home header says "Player" for a merchant.
  - Messages → the Direct filter still lists the system notice row.
  - At launch, `config/features` is refused once while the session is still a guest. It is retried with the token after
    restore and returns 200, so it is harmless.
