## Root causes and proposed fixes (product code is not changed on this branch)

### R1 — The activity page reached from a topic has no sign-up and no play entry (app) — HIGH
- Repro: Explore → topic 992001 → 立即报名 → choose 「E2E 免费体验场·老城三章」 → activity detail. No 立即报名 pill and no "Play" row (`shots/05c-activity-bottom.jpg`).
- Cause: `App/PlatformConsumerSessionOwner.swift:46` builds `ActivityDetailView(id: $0, reader: session)`. `registrationEnabled` defaults to `false` (`App/ActivityDetailView.swift:9`, gate at `:430`), and `playReaderForActivity` is nil, so `activity.openPlay` is never shown. Club activities are deliberately left off the public shelf (`ApiActivityController.java:265-275`, `PUBLIC_SHELF`), so for 992031 this is the only path. Sign-up and play are therefore impossible in the app.
- Fix: build it the same way as `App/SessionHomeFeedView.swift:141`: `ActivityDetailView(id: $0, reader: session, playReaderForActivity: { session.playReader(for: .activity($0)) }, registrationEnabled: true)`.

### R2 — DM `im/send` refused inside the app (app) — HIGH (was F4)
- Repro: Passport → Messages → Start conversation → member 9009 → Start chat → type → Send → "The outcome is unknown". Log: `composition refused or failed POST /prod-api/api/im/send: notConfigured` (`requests.L06-im.log`, `shots/L06c-dm-sent.jpg`).
- Cause: DMs are sent by `MessageActionService.send` (`Core/MessageActionService.swift:34`, built at `App/AppSession.swift:7348`). It uses `AuthRequestBuilder.makeFormRequest`, which leaves `httpShouldHandleCookies == true`. The only admission for `api/im/send` in `ReviewedProductionFormMutationRoute.acceptsPlayerWrite` (`App/ReviewedPlayerWriteLeases.swift:24-28`) goes through `NativeChannelTextRoute(request:)`, which rejects any request with `httpShouldHandleCookies` (`Core/NativeChannelTextAuthority.swift:86`). Commit `34f866715` made the *test* turn cookies off, but the production DM sender still leaves them on.
- Fix: set `request.httpShouldHandleCookies = false` in `MessageActionService.send` and `sendReceipt` (`:34`, `:60`), as `NativeChannelTextService.swift:242,257` does. Add a composition test that drives `MessageActionService` itself rather than a hand-built request.

### R3 — `club/chat` refused inside the app (app) — HIGH
- Repro: Clubs → 城瘾跑团 → Club group chat → Enter group chat → "The group may already exist…" (`shots/L14a-group-chat.jpg`). Log: `composition refused or failed POST /prod-api/api/club/chat: notConfigured`.
- Cause (probable): `club/chat` is configured only as a `BusinessRuntimeRoute` (`App/ReviewedPlayerWriteLeases.swift:582`). `CompositionHTTPTransport.guardedSend` admits player writes only through `acceptsPlayerWrite`, whose path sets (`clubCommunityPaths` at `:228`, and others) do not contain `api/club/chat`. The JSON body `{"id":7001}` (`Core/ClubChatService.swift:29`) is also not one of the admitted club shapes.
- Fix: admit `api/club/chat` (POST, JSON `{id}` only, member context) in `acceptsPlayerWrite`, or route `ClubChatService` through the business-runtime transport that owns the `.clubChat` grant. Backend → 200 (`probes-backend.txt`).

### R4 — `club/access/me` refused inside the app; the backend also rejects form bodies (app + backend contract) — MEDIUM
- Every club detail visit logs `composition refused or failed POST /prod-api/api/club/access/me: notConfigured`. The club calendar then shows "部分信息缺失，请刷新重试" (`shots/13d-club-calendar.jpg`).
- The app's contract says form-encoded (`App/ClubAccessAndSettlementSectionView.swift:40,67`), but the backend answers `500 Content-Type 'application/x-www-form-urlencoded' is not supported`, and JSON `{"clubId":7001}` → 200 (`probes-backend.txt`).
- Fix: grant the read in the shipped composition and send JSON (app), or accept form bodies (backend). Agree on one contract first.

### R5 — Club post lists are never read: `clubCommunityReadApproval` is never granted (app) — HIGH
- Repro: Clubs → Posts, or club → Club posts → "Could not load. Please refresh." No request is logged (`shots/L07a-club-posts.jpg`, `shots/L08a-posts-tab.jpg`).
- Cause: `AppCompositionRoot.clubCommunityReadApproval` keeps its default `{ _ in nil }` (`App/AppCompositionRoot.swift:371` and `:995`). Nothing in App/ or Core/ assigns it, so `ClubCommunityReadComposition.makeService` (`App/ClubCommunityReadComposition.swift:16-24`) falls back to the dormant `CommunityDormantHTTPTransport`.
- Fix: issue a `ClubCommunityReadApproval` for signed-in China players in the reviewed composition, for `api/club/post/list` and the comment list. Backend `club/post/list` 7001 → 200 with the seeded posts.

### R6 — Club public activities never approved (app) — MEDIUM
- Club → 活动 → 公开活动 → "公开活动读取当前不可用" with no request (`shots/13c-club-public-activities.jpg`).
- Cause: `clubPublicTopicsApproval` keeps its default `{ _, _ in nil }` (`App/AppCompositionRoot.swift:373` and `:997`) and is never assigned, so `AppSession.makeClubPublicTopicsReader` returns nil (`App/AppSession.swift:6651-6654`).
- Fix: grant it in the shipped China composition.

### R7 — Channels entry never approved (app) — MEDIUM
- Club → Channels → "Not available right now" with no request (`shots/L14b-channels.jpg`).
- Cause: `nativeChannelManagementApproval` keeps its default `{ _, _, _ in nil }` (`App/AppCompositionRoot.swift:335`) and is never assigned, so `makeNativeChannelManagementFlow` returns nil (`App/AppSession.swift:157-167`, `App/NativeChannelManagementEntry.swift:66-70`).
- Fix: grant the channel directory and read approval for club members. The r2 backend serves the channels list and create.

### R8 — Entry code: "Codes aren't available for this account" (app) — HIGH
- Wallet → Show code, or Ticket details → Present pass → Show code. No request is sent (`shots/L05b-entry-qr.jpg`, `shots/L05c-present-pass.jpg`).
- Cause: `AppCompositionRoot.verificationCodeApproval` returns only `productionGateLeases.cityVoucherIssue(context)`, which covers kind `.cityVoucher` only (`App/AppCompositionRoot.swift:653-657`). `VerificationCodeService.enabled` is therefore false for the registration and ticket kind (`Core/VerificationCodePresentation.swift:88-91,165`).
- Fix: issue a registration/ticket verification-code grant for the signed-in owner of the registration.

### R9 — Profile edit fails to decode `user/info` (app; contract) — MEDIUM (F5 follow-up)
- `user/info` → 200 `{…"sysCategoryList":null}` with no `tagIds` (`requests.L11-profile-edit.log`). The screen shows "Your profile didn't load completely. Reload before saving." (`shots/L11c-profile-edit.jpg`).
- Cause: `Core/ProfileEditContracts.swift:66-71` falls back to `c.decode([Category].self, forKey: .sysCategoryList)` when `tagIds` is absent. That call throws on `null`.
- Fix (app): treat `null` or an absent value as no preferences (`decodeIfPresent … ?? []` → `tagIds = ""`). Alternatively, the backend could return `tagIds: ""` or `sysCategoryList: []`.

### R10 — Passport profile card never loads (app; contract) — MEDIUM
- Passport → "Your profile didn't load." on every visit, although `userInfo` → 200 (`shots/L11a-passport.jpg`).
- Cause: `MemberHomeService.identity` reads `userInfo` through `Payload<T> { let data: T }` (`Core/MemberHome.swift:273,303,315`). `/api/userInfo` returns the user under **`appUser`**, so decoding throws `malformedResponse`.
- Fix: decode `appUser` for `.userInfo`, or read `api/user/info`, which returns `data` with `followNum`, `friendNum`, `fansNum` and `balance`. The counters the card needs are only in `user/info`.

### R11 — My projects refused: `api/project/my` (app) — MEDIUM
- Settings → My projects → "This service is not configured". Log: `composition refused or failed POST /prod-api/api/project/my: notConfigured` (`shots/L12a-my-projects.jpg`). Backend → 200 `{total:0}`.
- Fix: admit the owner read in the composition.

### R12 — `homeContinuation.*` keys missing; Journey read not granted (app) — MEDIUM (F6, unchanged)
- No `.xcstrings` or fragment in `Resources/` contains any `homeContinuation.` key. The keys come from `Core/HomeSearchTabParity.swift:899-912`. Journey reads are still not granted.
- Fix: add the strings, and grant Journey reads or hide the row.

### R13 — Club post review says "Posting isn't available right now", yet Confirm succeeds (app) — LOW
- `shots/L07b-create-post.jpg` → Review → the sheet shows "Posting isn't available right now." with a Confirm button. Confirm → `club/post/create` 200 id 992053. A 9009 `club/post/list` read did not include 992053 yet (pending moderation or paging, not investigated).
