## How the app was pointed at TEST (DEBUG only; Release is unchanged)

`App/RegionalLaunchConfiguration.swift`, `#if DEBUG` only:

- `--e2e-test-host https://8120-agqyfqxs5vwolymtoibzq3fhde.instabox.tech` admits exactly that one host and no other.
  It reuses the shipped reviewed composition (`shippedComposition`) unchanged. `E2ETestHostTransport` sits under every
  reviewed route guard and rewrites `https://www.chengyinhub.com/prod-api/` to the TEST host. Any other request to
  the production host is refused, so nothing reaches production. It uses a separate session realm, `cn-e2e-test`.
  Every request is logged as `[E2E] METHOD URL -> status latency body`.
- `--e2e-grant-content-details` (probe only, beyond shipped behaviour): also grants `contentDetails: .activityAndTopic`,
  so the flows behind F2 can be exercised against the backend.
- `App/AppCompositionRoot.swift`: in DEBUG, `CompositionHTTPTransport.send` logs in-app refusals as
  `[E2E] composition refused or failed …`. The Release path calls the same `guardedSend` without logging.
- `python3 tools/check_release_config.py` → "Release config check passed".

Launch: `xcrun simctl launch <udid> invalid.example.questify.ios --e2e-test-host https://8120-agqyfqxs5vwolymtoibzq3fhde.instabox.tech`
Logs: `xcrun simctl spawn <udid> log stream --style compact --predicate 'eventMessage CONTAINS "[E2E]"'`

## Findings with exact repro

### F1 — Cold relaunch signs the player out; profile never loads (backend contract gap + app) — HIGH
- Repro: sign in as 13900000004 → kill the app → relaunch with `--e2e-test-host …`. The welcome screen shows again (`shots/01d-relaunch.jpg`).
- Request (`requests.01-relaunch.log`): `POST /api/userInfo -> 200 {"msg":"操作成功","appUser":{…"userId":9004,"userName":"13900000004","nickName":null,…},"code":200}`. It has no `role`.
- App: `Core/AuthChannelService.swift:103-110` `currentAccount(token:)` passes `loginFallbackRole: nil` on restore, so an empty role → `APIError.malformedResponse` → the session is dropped. The login path survives only through the login-role fallback. The Passport profile card fails for the same reason (`shots/11b-passport-2.jpg`).
- Backend: `ApiLoginController.userInfoView` leaves `role` out of its whitelist and returns `nickName: null`. `POST /api/user/info` returns `role:"player"` and `nickname:"玩家小城"` (`probes-backend.txt`).
- Fix (either side): add `role` and `nickName` to `/api/userInfo`, or persist the login role and pass it on restore.

### F2 — Topic/activity detail is never approved in the shipped composition (app) — HIGH
- Repro: home → tap "E2E 探店日一期" → "Route details / Details aren't available right now" (`shots/02c-topic-detail.jpg`). No request is sent.
- Cause: `RegionalLaunchConfiguration.reviewedDeployment` builds `ReviewedAppDeployment` without `contentDetails`, so `AppCompositionRoot.readAvailability(.contentDetail)` returns `.detailReadNotApproved` (`App/AppCompositionRoot.swift:680`).
- With `--e2e-grant-content-details`, `POST /api/topic/info-to-user` returns code 200 and the page renders (`shots/04b-probe-topic-detail.jpg`), so the backend is fine.
- Impact: blocks flows 4, 5, 9 and every detail-dependent path in production too, because the override reuses the shipped composition.

### F3 — Roam location consent is never recorded on the server (app) — HIGH
- Repro: Roam tab → Go → "Agree and go" → "Needs a quick check / That didn't go through" (`shots/03c-roam-agreed.jpg`).
- Request: `POST /api/roam/reveal -> 200 {"msg":"请先明确同意漫游定位；撤回后不会接收新位置","code":500}` (`requests.03-roam.log`).
- Cause: the app never sends a `roam_location` AGREE. `ComplianceSubject.roamLocation` is used only for REVOKE (`Core/AccountComplianceCoordinator.swift:443`). Settings → Roam location consent offers only "Withdraw consent" and says "Consent has not been revoked" (`shots/03d-roam-consent-settings.jpg`).
- Backend accepts it: `POST /api/compliance/consents {"docType":"privacy_policy","scene":"roam_location","eventType":"AGREE","requestId":"<new>","expectedRequestId":""}` → code 200 (`probes-backend.txt`). Without `expectedRequestId` the backend answers 409 `定位授权状态已变化，请重新明确选择`.

### F4 — Live routes refused inside the app: `club/home`, `im/send`, `coop/list` (app) — HIGH
- Repro: the Clubs tab (`shots/07b-clubs-tab-2.jpg`, `shots/08a-posts.jpg`); Passport → Messages → compose → member 9009 → Start chat → send "E2E hello from 9004" (`shots/06e-sent.jpg`).
- Log: `[E2E] composition refused or failed POST /prod-api/api/club/home: notConfigured`, the same for `/api/im/send` and `/api/coop/list` (`requests.07-clubs.log`, `requests.06-im.log`).
- All three are `.liveInProduction` in `Core/ChinaReviewedRouteCapability.swift`, but `CompositionHTTPTransport.guardedSend` (`App/AppCompositionRoot.swift`) has no admission for them under the shipped deployment.
- Backend: `club/home`, `club/list` and `coop/list` return code 200 (`probes-backend.txt`). `im/send` is blocked on TEST by B2.

### F5 — Profile edit cannot load: `user/info` refused in the app (app) — MEDIUM
- Repro: Passport → Settings → profile card → "Your profile didn't load completely. Reload before saving" (`shots/11d-profile-edit.jpg`).
- Log: `[E2E] composition refused or failed POST /prod-api/api/user/info: notConfigured`. The backend returns code 200 with the full profile.
